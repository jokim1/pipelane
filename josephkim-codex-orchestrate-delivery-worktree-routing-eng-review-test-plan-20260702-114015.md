## What Already Exists

- Reuse the existing orchestration ledger and slice records, adding optional run-level source snapshot and baseline preflight fields without replacing legacy records.
- Reuse `buildReviewRunRecord`, `collectChangedFiles`, `skipReasonForGate`, `whenChanged`, and the review-gate catalog/order plumbing instead of adding a second review runner.
- Reuse current worktree creation, status/analyze output, and finalize/cleanup flows; the new source snapshot helper supplies the review base and cleanup evidence.

## New Behavior Under Test

- Run-level source snapshot refs under `refs/pipelane/orchestrate/<run-id>/source`.
- Run-level baseline preflight status, accepted-failed evidence, and dispatch blocking.
- Strict docs-only profile inference from changed files relative to `sourceSnapshot.reviewBaseRef`.
- Profile-aware gate skipping, known-red baseline handling, ignored-output evidence, and orphan snapshot-ref recovery.

## Not In Scope

- Fixing the already-red full `npm test` suite.
- Changing AI review model behavior or adding new worker infrastructure.
- Changing non-orchestrate review flows except where shared review helpers are reused.
- Automatically deleting ignored outputs with destructive cleanup such as `git clean -fdX`.

## Affected Pages/Routes

- CLI `/pipelane orchestrate` source preflight, baseline preflight, prepare, dispatch, review, outline/status/analyze/finalize.
- CLI `/pipelane review` command-gate execution order, profile-aware gate selection, and ignored-output evidence.

## Deterministic Rules To Assert

- Profile inference computes changed files relative to `sourceSnapshot.reviewBaseRef`.
- A slice is `docs-only` only when there is at least one changed path and every classification path is under `docs/`, exactly `README.md`, exactly `CHANGELOG.md`, or a root-level `*.md`/`*.mdx`.
- Empty diffs and inherited-source-snapshot-only diffs default to `implementation` so they do not skip full-suite gates by vacuous truth.
- Deleted files classify by the deleted path. Renamed/copied files classify by both old and new paths; a rename crossing the docs/code boundary is `implementation`.
- Any change under `src/`, `bin/`, `scripts/`, `templates/`, `test/`, package manifests or lockfiles, TypeScript config, orchestration/review config, CI config, or any mixed docs/code diff is `implementation`.
- For `docs-only`, unscoped full-suite gates such as `npm test`, `npm run build`, and `npm run typecheck` are skipped with reason `docs-only profile, gate has no matching whenChanged path`; gates whose `whenChanged` matches docs paths still run.
- Accepted baseline failures remain `accepted_failed`; matching implementation-slice command gates become baseline-red `pending` unless a targeted replacement gate passes or an audited per-slice bypass is recorded.
- A targeted replacement gate clears a baseline-red pending command only when the passing gate declares `replacesBaselineCommandId: <accepted-baseline-command-id>`; a passing unlinked gate does not clear the pending state.
- Snapshot cleanup failure is visible but recoverable: finalization records a warning in the ledger, and cleanup/finalize retry may delete only the matching inactive run ref.

## Harness Requirements

- Source snapshot, bundle digest, namespaced ref, rollback, cleanup, orphan-ref recovery, review-base comparison, and concurrent-run tests must run against a real temporary git repository fixture, not mocked git.
- The real-git fixture must create actual commits, refs, worktrees, tracked changes, staged changes, untracked non-ignored files, ignored files, deletions, and renames where those cases are asserted.
- Command execution outcomes, timeouts, and ignored-output creation may use controlled test commands, but the git/ref operations around them must remain real.
- Ledger concurrency tests must use two run ids with separate per-run ledger paths under `.git/pipelane-state/orchestrate/runs/<run-id>/orchestration.json`, separate per-run `mutation.lock` directories, and per-run integrity heads.
- Interleaved writes from two active runs must leave each run's ledger fields intact and unmixed; a mutation-lock timeout or integrity-head mismatch is the expected failure for concurrent mutation of the same run.

## Key Interactions to Verify

- Dirty parent worktree blocks unless acknowledged: command returns nonzero, message contains `dirty parent worktree` and `acknowledge dirty source`, no source snapshot ref is created, and no slices dispatch.
- Acknowledged dirty source creates a source bundle and local source snapshot ref without mutating the parent worktree: ledger records acknowledgement reason, bundle path, bundle digest, `snapshotRef`, `snapshotSha`, and `reviewBaseRef`.
- Baseline preflight runs from the source snapshot ref and records pass/fail/accepted-failed state: ledger stores each command id, command text, exit code, timeout flag, duration, and summary path.
- Failed baseline blocks dispatch until accepted: command returns nonzero, message contains `Baseline preflight failed`, baseline status is `failed`, and slice statuses remain unstarted.
- Accepted baseline failure allows dispatch without hiding risk: baseline status is `accepted_failed`, accepted reason is stored, and the original exit code/timing/summary remain unchanged.
- Slice review compares against `sourceSnapshot.reviewBaseRef`, not always `origin/<baseBranch>`: inherited source snapshot files are absent from the slice changed-file set.
- Docs-only slices skip unrelated full-suite gates with explicit reasons and still run docs-matching `whenChanged` gates.
- Known-red baseline command gates remain baseline-red `pending` unless targeted replacement evidence or audited baseline-red bypass exists.
- Review gate order resolves through the shared ordering resolver and persists the resolved order in the review record.
- Ignored outputs such as `dist/` are recorded and warned on without failing an otherwise successful command gate.

## Observable Assertion Matrix

| Scenario | Expected command/review result | Required persisted evidence |
|---|---|---|
| Dirty parent, no acknowledgement | Nonzero result; message contains `dirty parent worktree` and `acknowledge dirty source`; dispatch is blocked. | No `sourceBundle`; no `snapshotRef`; no prepared slice worktrees. |
| Dirty parent, acknowledged | Success through source preflight; parent worktree status before/after is unchanged. | `acknowledgedDirtySource.reason`, `sourceBundle.artifactPath`, `sha256`, `snapshotRef`, `snapshotSha`, and `reviewBaseRef`. |
| Source snapshot creation fails before ref exists | Nonzero result; actionable source-snapshot message; dispatch is blocked. | Ledger records failed source preflight without a dangling snapshot ref. |
| Source snapshot ref created, later setup fails | Nonzero result; actionable partial-snapshot message; dispatch is blocked. | Best-effort rollback deletes the namespaced ref or records cleanup warning evidence. |
| Baseline command passes | Baseline status `passed`; dispatch may start. | Command id, command text, exit code `0`, `timedOut=false`, duration, summary path. |
| Baseline command fails | Nonzero result; message contains `Baseline preflight failed`; dispatch is blocked. | Baseline status `failed`; original nonzero exit code, timeout flag, duration, and summary path retained. |
| Baseline failure accepted | Accept command succeeds only with nonblank reason; dispatch may start. | Baseline status `accepted_failed`; accepted time/user/reason; original failure evidence unchanged. |
| Baseline accept invalid target | Nonzero result; no status transition. | Unknown command id, already-passed command, and blank reason each leave ledger unchanged. |
| Docs-only slice | Review can complete without unscoped full-suite gates. | `reviewProfile=docs-only`; `npm test`, `npm run build`, and `npm run typecheck` skipped with profile/path reason; matching docs `whenChanged` gate runs. |
| Mixed docs and source slice | Full implementation review runs. | `reviewProfile=implementation`; configured command gates and AI/code review gates are not skipped by docs-only logic. |
| Empty or inherited-only diff | Full implementation review runs. | `reviewProfile=implementation`; full-suite gates are not skipped by docs-only logic. |
| Docs deletion-only diff | Docs review behavior applies. | Deleted path under `docs/` is included in classification paths and can produce `reviewProfile=docs-only`. |
| Source deletion-only diff | Full implementation review runs. | Deleted path under `src/`, `test/`, `scripts/`, `templates/`, or config/package paths produces `reviewProfile=implementation`. |
| Rename crosses docs/code boundary | Full implementation review runs. | Both old and new names are included in classification paths; any non-doc path produces `reviewProfile=implementation`. |
| Known-red implementation gate | Review is pending/baseline-red until alternate evidence exists. | Matching full-suite gate result is not `passed`; baseline-red reason points to accepted baseline command. |
| Linked replacement gate passes | Baseline-red pending state can be resolved. | Passing gate records `replacesBaselineCommandId` matching the accepted baseline command and persists replacement evidence. |
| Unlinked replacement-like gate passes | Baseline-red pending state remains. | Passing gate has no matching `replacesBaselineCommandId`; known-red command stays pending. |
| Baseline-red bypass | Completion allowed only with nonblank audited reason. | Bypass evidence is stored separately from command-gate pass/fail evidence. |
| Ignored output created | Command gate keeps its real exit status. | Watched-output mutation lists created/modified/deleted paths and a warning when later gates inherit them. |
| Cleanup failure | Finalize/cleanup completes with visible warning, not silent success. | Ledger cleanup status/warning identifies the failed ref deletion and retry target. |
| Orphan ref recovery | Retry deletes only inactive matching run refs. | Namespaced ref is removed; other run refs remain; source digest and snapshot SHA stay in ledger. |
| Concurrent runs | Both runs can snapshot/finalize independently. | Refs, run ledgers, mutation locks, and integrity heads are isolated by run id; cleanup for one run never deletes or writes the other's state. |

## Edge Cases

- Source bundle excludes ignored files and discloses that exclusion.
- Source snapshot creation failure blocks with an actionable message.
- Partial source snapshot setup rolls back a created namespaced ref or records cleanup warning evidence if rollback fails.
- Source snapshot ref cleanup removes `refs/pipelane/orchestrate/<run-id>/source` while preserving ledger evidence.
- Cleanup/finalize retry removes orphan snapshot refs only for inactive matching runs and never for a different run id.
- Concurrent orchestrate runs use isolated snapshot refs and preserve each other's refs during cleanup.
- Baseline accept rejects unknown command ids, passed commands, and blank reasons.
- Baseline-red bypass rejects blank reasons and does not rewrite failed command evidence as passed.
- Legacy ledgers without new fields remain readable.
- Malformed present source snapshot, baseline preflight, review profile, accepted failure, or ignored-output evidence fails closed.

## Critical Paths

- Plan from dirty source -> acknowledge -> create source snapshot -> baseline preflight -> accept known-red baseline -> prepare slice worktrees from snapshot -> review against snapshot base.
- Docs-only slice -> profile inference from `reviewBaseRef` -> unrelated full-suite gates skipped -> review record carries skip reason.
- Implementation slice -> known-red full-suite baseline -> targeted replacement or audited bypass -> final review status remains explicit about baseline risk.
